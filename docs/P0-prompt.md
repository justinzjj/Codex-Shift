## 第一优先级：桌面控制路径

1. 确认实际安装的 Codex 应用、版本及当前账号可选的两组模型与强度。记录证据及验证环境。
2. 核对正式支持的快捷键、命令或接口，验证是否能对当前聊天指定模型、指定思考强度，并分别读回。打开选择器不能算切换成功。
3. 验证切换模型是否重置强度；重复选择是否幂等；草稿是否保留；多个窗口／聊天如何定位；回复运行中是否能可靠识别和安全拒绝操作。
4. 若需要 UI 自动化，先确认工具与应用允许访问，评估可访问性控件及语义定位；不要用固定坐标或盲目按键宏充当可靠闭环。
5. 交接明确记录 Computer Use 曾拒绝访问 Codex。不要通过 AppleScript、辅助功能脚本、调试端口、私有数据库或其他通道绕过已知访问限制。若仍受限，说明具体限制，让用户完成最少必要的手动验证；手动可操作不等于助手自动化已经可行。
6. 不修改全局 config.toml，不通过另起 CLI 会话、新建聊天或发送消息冒充当前聊天切换。不要发出任何测试消息。若需修改当前聊天设置，先记录原值，验证后恢复；无法安全恢复时明确告知。

## 第二优先级：硬件输入

1. 验证 LNKSY-OLED-KEYBOARD 是否连接，VID/PID 是否为 0xAEAE/0x6066，以及 VIA 是否识别。
2. 读取实际设备配置并先备份。磁盘保存文件包含四层，而源码默认三层，不能假定当前固件与源码一致。
3. 确定两个不会破坏层切换功能的实体键，用 F13/F14 作为候选测试键码。若键位无法从材料或连接设备明确定位，让用户指定两个键，不自行猜测。
4. 在备份后可通过 VIA 配置已明确的两个键，验证按下／释放、长按重复、不同层行为和重连。若无法操作设备，给出最少手动步骤并标明未验证。
5. 评估 macOS 的设备级输入监听，验证能否区分该小键盘与普通键盘，以及权限需求和键码传播／快捷键冲突。不独占整块键盘导致其他键不可用。
6. 不刷固件、不安装来源不明的工具；保留恢复原键位的方法。设备未连接不能记作硬件通过。
